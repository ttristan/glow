# CLI run artifacts

1. Health runs save `replay.json` under `packages/glow-cli/artifacts/cli/<UTC-date>/<UTC-minute>/run-<id>/` and print its path on stderr. Set `GLOW_CLI_ARTIFACT_DIR` to change the root. Help and invalid commands produce no recording. Artifacts are ignored by Git.
2. The replay format matches the reference: `{"events":[{"ms":0,"kind":"action","data":{}}]}`. Events are ordered by elapsed milliseconds; `data` is JSON. Health records an action and response or error. Credentials, query parameters, response bodies, and user-facing errors are omitted. Future controllers can record their own `action`, `server`, `plan`, and other events using `CliRunRecorder`.
3. Run `npm run --silent cli -- replay /absolute/path/to/replay.json` and open the printed loopback URL. Stop the viewer with Ctrl-C. It displays event data, actions, reasons, and plans without executing recorded commands. Pause, seek, or select speeds up to 20×. For a specific paused time, append `#replayAt=MILLISECONDS` to the URL.
4. Capture screenshots using a browser or headless browser against the viewer URL. Choose timestamps from the replay; use the same browser session for multiple captures. Wait for `domcontentloaded` and `document.documentElement.dataset.replayReady === 'true'` before capture. Keep screenshots beside the replay and out of source control unless requested.

The browser module `packages/glow-cli/src/replay-player.js` exports `createReplayPlayer(events, { reset, apply, update })`. A client supplies callbacks to reset its state, apply each event, and update playback controls. The player exposes `seek`, `play`, `pause`, `setSpeed`, and `destroy`; backward seeking resets state and replays events from the start. A future game client must render its own state; the event viewer does not reconstruct gameplay or browser UI events.
